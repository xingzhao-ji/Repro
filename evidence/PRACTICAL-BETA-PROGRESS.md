## Reproducible package and platform scope

Observed configurations are macOS arm64 (development workflows pass; htmx stability remains failed) with Node 26.7.0, Playwright 1.64.0 and Chromium 156.0.8078.4 using existing development dependencies, and capsule-only Linux arm64 in a new owned VM with an initially empty daemon. Each case acquired dependencies/browser twice without build cache: for the full workflow input and independently for its reduced export. Only the pinned public base layer is reused within the cohort. The contexts contain no original workspace, host bind mounts, ambient npm/browser cache, credentials or host application services. Replay has no external network, LLM, account/API key, proprietary viewer or database requirement.

Declared prerequisites are Node ≥24, npm, the exact lockfile, pinned Chromium and its OS libraries; only Node 26.7.0 was tested. Acquisition needs public npm/browser/system repositories. The Docker recipe pins the Node Debian base by digest, but system repositories are not snapshotted, so bit-identical OS rebuilds are not claimed. Runtime uses unprivileged `node`, verified Docker `--init`, enabled Chromium sandbox, network none, read-only root, all capabilities dropped, no-new-privileges, private cgroup namespace and owned named evidence volumes. `/tmp` and `/dev/shm` are each capped at 256 MiB. No Docker socket is exposed to the workload.

## Remaining native stability defect

At htmx fixed pair 15, the frozen assertion executed once and observed the correct `['true', 'clicked']` values. Browser shutdown then missed the existing acknowledgement limit. [The actual retained result](../.repro-runs/readable-fixed/202a6e1c-caea-4f7b-a079-1b087e7dd846/evidence.json) is `inconclusive`, category `environment`, reason `CLEANUP_FAILED`; its `.profile` remains preserved. The adapter returned after about 2.187 seconds, while the enclosing command exited at 5.970 seconds. Subsequent empty process/TMPDIR censuses do not establish timely product cleanup or remove that profile.

The original final repetition cohort therefore remains **69 completed / 1 failed / 50 unattempted**. Marked's later independent continuation does not rewrite that denominator. A bounded shutdown diagnostic ran five additional htmx buggy/fixed pairs with public close-call/event/settlement timestamps and unchanged deadlines. All ten returned expected outcomes; close settlement took 11.297–12.415 ms. The delay did not recur. These are diagnostic observations, not replacement acceptance evidence; they do not establish a Playwright/Chromium/host root cause. [Diagnostic findings](../.repro-runs/practical-beta/htmx-close-diagnostic-v1/FINDINGS.md).

Remaining work is to establish the cause and make an evidence-backed lifecycle repair, then complete the native htmx 20-pair gate and any candidate verification affected by that repair. Increasing the acknowledgement timeout, accepting eventual cleanup, or repeatedly rerunning until green is not a repair. Switching to an ephemeral context could change shutdown behavior but is unproven; no speculative implementation or security change was made. This is a runtime stability failure, not a service restriction or a request for new permission.
