# Frozen inspection evidence contract

Version 1. This increment prepares a local evidence packet, not P/L renderers, a participant study, or proof of interface benefit. The source is actual execution of the registered synthetic search fixture. Five jobs from one session supply a record, reduction, comparison, finalized export, and cancelled reduction. New IDs do not create independent failure families.

The public TypeScript contract is `scripts/hci-case.ts`. A packet has exactly `schemaVersion`, `caseSha256`, and `evidence`. Its SHA-256 is the existing canonical JSON digest of `evidence`, excluding the envelope. Source-file hashes identify original bytes. Neither kind of hash authenticates the author or establishes an observation independently.

`evidence` contains its version/classification/mode, case and family identity, source commit/runtime inventory/database/file identities, one saved session, five unique role-to-job bindings, a default selected job, all five jobs, two inert export documents, explicit redaction records, and excluded artifact kinds. Each job contains its terminal job metadata without the request key, recorded result, chronological events, the exact `JobInputEvidence`, and every `TrialEvidence` index. A required field cannot be silently omitted. `null` input/result fields within unavailable inspector evidence retain their distinct meaning; a terminal job result itself cannot be null in this increment. Unknown fields, duplicate identities, unsupported enums, digest mismatches, and cross-session associations fail validation. Serialized trial-event messages are bounded to 65,536 UTF-8 bytes and parsed strictly before their original text can enter a validated packet. Duplicate object fields, including escaped-equivalent names and nested duplicates, are rejected rather than silently overwritten.

The roles are `record`, `reduction`, `comparison`, `export`, and `cancelled`, with operations record/reduce/verify/export/reduce respectively. The cancelled role must have cancelled status. These identify evidence resources, not claim judgments. No scoring keys, claim answers, facilitator hints, participant responses or contact/consent information may be added to the participant packet.

The saved session manifest is historical session state. Only each job's inspected saved input establishes that job's input. Preserve the selected earlier record's five actions and 10,000 ms limit alongside the later reduction's five-action input and 1,500 ms limit. Preserve rejected/inconclusive trials, cancelled baseline, unverified minimality, zero assertions and missing observations. Recorded decisions remain metadata when exact inspected evidence is unavailable. The comparison candidate retains the controlled input manifest digest while exposing its distinct fixed application identity.

## Freeze and read boundary

`freezeCase` reads only an explicit child of the repository's `.repro-runs`. The source must be quiescent: no `owner.lock`, SQLite WAL or SHM may exist. It never constructs `Ledger` or opens the source database with SQLite. It reads a bounded regular single-link database file, writes those bytes into a private scratch directory beneath `.repro-runs/hci-comparator`, opens only the scratch copy read-only with query-only mode, and reads the five selected jobs/session/events. Existing `inspectJobInput` and `inspectTrial` inspect the original artifact root through a structural read-only adapter. No runner, coordinator, browser or capsule execution occurs.

Before/after checks bind original source bytes and retain a sorted inventory of database and relevant saved manifest/result/execution JSON files. Missing evidence is recorded by the existing inspector; it must not be replaced by session state. Existing nonregular, linked, oversized or unsafe source paths are rejected. Source reads are bounded to an 8 MiB database and 512 KiB per JSON; the packet is bounded to 4 MiB. The trusted local workspace boundary does not claim protection against a hostile process replacing ancestor directories concurrently.

Output is a new `.json` file beneath `.repro-runs/hci-comparator`, outside the source tree. Scratch cleanup must succeed before publication. A complete validated packet is written to a private temporary file and atomically linked into place without overwriting an existing target. A pre-publication failure leaves no completed packet. If publication or its temporary-file cleanup fails, the freezer attempts to remove only its own newly linked output and reports failure; inspect that output before retrying because an underlying filesystem failure could prevent cleanup. Scratch cleanup affects only the directory created by this invocation and preserves the primary failure in private error causes. Generated data stays ignored and is not automatically published.

## Public projection

The projection preserves observations, assertions/counts, application/input/harness identities, timestamps, budgets, decisions and availability. Request keys are omitted. Artifact paths become `evidence-artifact:<jobId>:<runId>:<index>`; export paths become `local-export:<jobId>`. Each omission/replacement has a JSON-pointer redaction record without the original value. Unregistered explanation/event text is withheld before serialization, with a redaction record. Source-file hashes preserve a local provenance link to the original bytes. Raw trace and screenshot bytes and the runnable export bundle are excluded explicitly and equally from future conditions.

`exportDocuments` is required and contains exactly one `README.md` and one `replay.test.mjs`, each with `name`, `sha256`, `bytes`, and `text`. These are inert plaintext references for T6 inspection, not executable downloads or permission to run their instructions. Each document is at most 65,536 UTF-8 bytes. The pure validator accepts only the reviewed public generator templates: README SHA-256 `0d8a36d407095b7d8eb8602172d93298c1370a441a922fc1b8ecbccc31e846d0` (7,447 bytes), and readable test SHA-256 `e3c1bbd15079c02cf99365a9a952887f0d085ccfbfea76a23b54daeb411a6ad8` (1,310 bytes). Unreviewed/private text is rejected rather than sanitized into a different document.

The freezer reads only `exports/<roles.export>/{README.md,replay.test.mjs,integrity.json}` beneath the explicit source ledger root. It never follows `result.path`; the recorded path must equal that fixed owned directory. Strict bounded UTF-8 reads, regular single-link/ancestor checks, the integrity manifest's per-document hashes/byte counts and selected export manifest digest, and before/after source hashing bind the displayed text. All three source files enter the inventory, while the integrity JSON itself and other executable files are not added as participant document text. This is validation of these two references and their recorded association, not a new verification of every capsule payload file or clean-machine replay. Both future conditions must expose the identical text as text, with no execution control.

Redaction pointers normally address packet evidence fields. For a serialized trial-event message, the suffix `/message/reason` addresses the `reason` field after parsing that message as JSON; it is a documented embedded-JSON extension, not ordinary pointer traversal through a string. Every placeholder/withheld field must have a matching record, and orphan transformation records are rejected.

Both the freezer's `Unregistered recorded text withheld.` marker and the inspector's `Recorded explanation is withheld because it is outside the registered public evidence text.` marker require declarations. A marker already present in the projected source keeps its exact text and still receives one declaration; ordinary registered explanations do not. A historical accounting defect must be repaired into a new packet with explicit versioned provenance, predecessor/successor hashes and exact changes. The original packet, ledger, observations and source inventory remain intact. Relocated historical export paths must not be rewritten or accepted by weakening the freezer's owned-path check.

These transformations affect presentation-only fields, never assertion inputs or observations. If a required manifest or observation contains unsupported/private values, reject the packet rather than changing its failure-relevant facts. The same projected packet must later feed both P and L. No condition may independently resanitize or reinterpret recorded evidence.

## Interface and later fidelity gate

Pure exports are `validateCase(unknown)`, `caseDigest(HciCase)`, `createPacket(unknown)`, `validatePacket(unknown)` and `parseCaseJson(text, maximumBytes)`. They perform no I/O. The shared serialized-JSON parser rejects duplicate fields at every depth and enforces UTF-8 byte, 32-level nesting and 20,000-node bounds; its default maximum is 4 MiB, and callers may request a smaller maximum. `scripts/freeze-hci-case.ts` exports `freezeCase(options)` and import-safe `main(args)`; importing either file does not freeze data or start a service.

The CLI requires `--source`, `--output`, `--source-commit` and `--runtime-inventory-sha256`. Invalid, unsupported or identity-inconsistent source evidence returns an input diagnostic and exit code 2. Filesystem/runtime failures return an environment diagnostic and exit code 1. Diagnostics contain fixed public text; original errors remain only in private causes, including when scratch cleanup also fails. It binds the reviewed five job IDs; programmatic tests pass explicit roles and case ID. A successful freeze is not a claim that P/L parity or screen-reader/keyboard/native-zoom usability has been tested. Renderers, identical search/evidence access, fixed operations, interactive parity review and actual accessibility evidence remain later work under the study protocol.
