## Mechanism and bounded state

`createIncrementalDecoder(given)` accepts `write(chunk)`, `finish()`, `abort()`, and `inspect()`. `write` returns undefined. `finish` returns the final graph once, only after complete valid JSON/tagged-graph grammar. Abort and any parse failure erase the partial root, reference map, parser frames and scalar state; subsequent writes/finish reject. `inspect` returns only numeric/boolean counters, never graph references. Finish also clears retained internal references.

The parser creates ordinary objects/arrays directly, registers IDs before their children, and retains aliases, cycles, own undefined, property order, UTF-16 code units including lone surrogates, finite numbers and negative zero, NaN/infinities, and bigint. It uses a single scalar token, a grammar stack bounded by `maxDepth + 2`, and a reference table bounded by `maxNodes`. Data/key/bigint string tokens retain the unchanged `maxStringUnits` bound; fixed protocol tag/special-number labels have independent 2/9-code-unit bounds because they never consumed the predecessor's data-string budget. A numeric lexeme is bounded by the unchanged total `maxEncodedUnits`; the remote encoder normally emits short canonical numeric text. Contiguous token spans are appended once per input span, rather than character by character. Input UTF-16 units, node count, and depth bounds are unchanged.

`transferMeasurement` validates every bounded chunk while consuming it, validates EOF and the unchanged metadata fields, attempts encoded-handle disposal, then calls `finish`. It returns no graph before all those steps succeed. Every failure aborts the parser and retains the original rejection reason, including falsy reasons; disposal failures are surfaced without repeated disposal attempts. The original handle is disposed before the first chunk as before. Invalid syntax can now reject earlier: the predecessor test that feeds `x` forever expected a later size-limit error; the new parser rejects the first malformed chunk. Both reject and dispose, but the frozen test's specific error-category expectation must be reported separately rather than altered silently.

## Memory limits and recommendation

Eliminating the intermediate receiver graph is a concrete allocation change, not evidence of an achieved memory peak. The partial final Node graph now overlaps the browser-side graph while chunks are read, whereas the predecessor disposed the browser graph before its final decode. String representations can also retain input-string backing storage, depending on the engine. Therefore neither removal of the intermediate representation nor offline fixture equality proves a reduction in process RSS or container peak memory. No forced GC is introduced in the candidate.

Keep this candidate uninstalled. Use the independently bound offline allocation/RSS results, including adverse trials, to decide whether this receiver is a promising implementation direction. A future integration still needs independent source binding and scoped verification. It does not resolve the stopped pilot's memory gate, authorize another pilot, or resolve the separately pending observation-lifecycle decision.

Independent functional clearance binds the final candidate before and after execution: 86/86 new streaming groups (including 1,728 deterministic wire mutations), 13/13 instrumented cleanup groups, and 107/108 frozen predecessor groups. The small-string-budget finding is closed. This is functional clearance for an uninstalled offline candidate, not a runtime or memory-gate clearance.
