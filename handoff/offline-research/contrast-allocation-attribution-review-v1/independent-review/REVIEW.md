# Focused independent allocation review

**No smaller correction is supported by the existing evidence that both avoids remote/client graph overlap and preserves the frozen current failure semantics.** Keep both transport prototypes uninstalled and the original 107/108 regression outcome intact. This review selected no code change and ran no test, benchmark, browser or container.

The concrete sequencing is visible in the [predecessor receiver](../../contrast-transport-investigation-v1/author/transport.mjs) and [incremental receiver](../../contrast-incremental-receiver-v1/author/transport.mjs). The predecessor retains wire chunks, validates metadata, disposes the remote handle, then builds the decoded graph. The current candidate constructs its final graph during reads; the remote encoder's strong reference map and active root traversal retain the source graph during that period. Handle disposal does not itself prove garbage collection or lower RSS.

| Possible change | What it establishes | Why it is not a supported correction |
| --- | --- | --- |
| Buffer chunks, dispose remote, then feed the incremental decoder | Separates remote ownership from decoded-output construction on successful transfers | Restores whole-wire retention and changes failure ordering; no measured benefit for this combination exists. |
| Replace the encoder's strong map with weak references | Could remove one strong-reference source | Active root traversal still retains the graph; IDs also require separate accounting. It does not remove overlap while reading. |
| Clear encoder references at EOF | Could shorten some post-EOF retention | Output already grew alongside the source during reads; no observation attributes the peak to that short interval. Physical reclamation remains unmeasured. |
| Destructive traversal, spooling, or a separate validation pass | Could change lifetime or storage strategy | Introduces mutation, storage/error paths, or additional retained state and work; none is a smaller verified change. |

Failure precedence is a concrete blocker to the buffered variant. With malformed first-chunk data followed by a later read or metadata failure, the current parser rejects the syntax first and performs cleanup. Deferring parsing permits the later failure to become primary. If disposal also fails, the current path can retain syntax plus disposal in an `AggregateError`; a dispose-before-decode variant can return only the disposal failure and never discover malformed data. Falsy rejection values and one-attempt disposal must also remain intact. Relative to the older predecessor, exact parser-error equivalence is likewise unestablished. Preserving successful measurement values alone is insufficient.

Existing measurements do not establish overlap as the cause of the RSS result. The [benchmark worker](../../contrast-incremental-receiver-v1/benchmark/worker.mjs) deliberately retains its outer `source` variable throughout each complete-transfer simulation in both modes. It therefore does not measure reclamation of that graph after fake handle disposal. The [paired summary](../../contrast-incremental-receiver-v1/benchmark/summary.json) retains two complete-transfer RSS regressions and one improvement; isolated decoding improves RSS but is slower. Process high water includes setup and assertions, and sampled heap readings do not identify allocation stacks, retained objects or string backing storage.

I independently reread the historical pilot: **268 resource samples and 28 driver snapshots**, peak **943,087,616 bytes**, first final-peak observation at sample **261**. Process records contain identity/state/thread fields, not RSS. The driver snapshot after row 10 records 173,333,048 bytes of used heap and 423,878,656 bytes of RSS; after row 11 these are 66,874,848 and 413,364,224 bytes. That difference illustrates why used heap, RSS and cgroup high water cannot be interchanged or subtracted into a causal explanation. The peak was observed between those boundaries, not attributed to a particular allocation. [Bound source and metric readback](evidence-review.json).

It fixes one native-transport job with the original 12 rows and 50 controls; adds bounded, separate numeric telemetry; retains the original process-state fingerprint; and keeps the 896 MiB gate, 90/120-second limits, 100 ms unreferenced timer and no-hold lifecycle. Memory fields must never affect cleanup/zombie acceptance. Missing post-close evidence remains missing.

Review corrections incorporated before this plan was bound: preserve original timing assignments and place markers outside their directly timed regions; cap each `memory.stat` read at 4 KiB plus a truncation sentinel; preflight sidecar byte estimates against the archived and maximum envelopes. The 1 MiB sidecar remains inside the existing combined 4 MiB budget and completion reserves. Missing, truncated or capped telemetry means attribution is incomplete, not zero or a gate pass.

A single such pilot can narrow process/category/phase questions only. It cannot prove graph-overlap causation, separate native browser serialization from client decoding without distinguishing evidence, or demonstrate a counterfactual memory saving. Report measurable collection counts, bytes and read/write durations; total causal instrumentation perturbation remains unknown. No profiler or lifecycle extension is implicitly authorized. Stop pending the decision on preparing/reviewing that diagnostic patch and its single bounded pilot.
