# Focused allocation/lifetime review

**No measured, error-invariant local correction is established.** Keep both prototypes uninstalled and preserve the frozen incremental result of **107/108**, including its earlier malformed-stream rejection. The existing records justify a narrow lifetime hypothesis, not another implementation or runtime pilot. This review read existing evidence only; it ran no tests, benchmarks, browser/container jobs, or candidate code.

## Concrete ownership and error ordering

The predecessor encoder holds every visited object in `seen`; its suspended traversal also retains its active source objects (`contrast-transport-investigation-v1/author/transport.mjs:12`, `:31`, `:43`, `:52`). The original handle is released before reads, but the encoded handle still owns that traversal. The predecessor receiver accumulates bounded chunks, validates EOF/metadata, awaits encoded-handle disposal, and only then joins/parses/decodes (`:108–121`). Its deliberate ownership sequence is remote graph plus encoded strings, then encoded strings plus intermediate tagged graph plus final graph. Handle disposal releases a reference; it does not prove immediate garbage collection or an RSS drop.

The incremental candidate builds final containers during `decoder.write(chunk)` while the encoded handle is still live (`contrast-incremental-receiver-v1/author/transport.mjs:125`, `:216–230`). It removes the complete joined string and intermediate tagged graph, but intentionally overlaps final receiver graph/reference-map allocation with the remote graph. Strings are built from input slices (`:155–160`, `:174–178`); retained backing storage is possible, not demonstrated by these measurements.

Failure order is material. The predecessor checks metadata and successfully disposes before parsing. The incremental candidate can reject syntax during reads, before metadata. Its cleanup then attempts disposal and may aggregate a syntax primary error with a disposal failure (`:223–235`). For malformed early input plus bad metadata, the prior metadata error can win while the incremental syntax error wins. For malformed early input plus disposal failure, the prior disposal failure can be the sole error while the incremental result can be an aggregate. These follow directly from control flow; this review did not execute new reproductions. An allocation-only change must not silently change those priorities.

## Plausible smaller changes, and their limits

| Option | Ownership effect | Error/evidence constraint |
| --- | --- | --- |
| Buffer the unchanged chunks, preserve the predecessor EOF/metadata/disposal sequence, then feed them to the incremental decoder and release consumed array slots | Avoids intentional live-handle/final-graph overlap and avoids the joined wire/intermediate tagged graph; restores bounded encoded buffering | The receiver-only experiment resembles its decode phase. No full-transfer run measures this arrangement. It restores predecessor error precedence but changes the incremental candidate's early-failure behavior; parser error categories also differ. It cannot be labelled error-invariant under both baselines. No implementation proposed for adoption. |
| Keep the predecessor decoder and explicitly release its chunk-array entries after successful join, before decode | A very small change could shorten explicit receiver chunk references; the predecessor already disposes before constructing the final graph | Preserves predecessor parse/error ordering and measurement data in source-level reasoning. However, no record shows whether V8 already considers those references dead, whether joined-string backing retains them, or how much memory is attributable to them. It retains the full intermediate graph and has no demonstrated gain. |
| Clear encoder `seen` only once EOF is reached | Could release redundant encoder references after traversal is complete, before handle disposal | Too late to prevent in-read overlap. Earlier clearing breaks stable backward-reference IDs. EOF reference cleanup has no attributed measurement benefit and does not force collection. Not an evidence-backed fix. |
| Validate while reading, buffer wire, then construct after disposal | Could preserve early syntax detection without early final-graph construction | Requires a separate validation-only grammar/reference/key state plus replay, doubles parsing, and introduces new consistency/error risks. It is not a smaller correction and is unsupported by current measurements. |

Dropping result fields, projecting evidence, mutating the source graph, collecting it forcibly, or spilling to new I/O would change the semantic/operational contract and is outside this review. None is recommended.

## What the measurements actually support

The full simulated transfer was higher in RSS in two pairs (**+5.261719**, **+5.421875 MiB**) and lower in one (**−12.949219 MiB**); every timing pair regressed. Receiver-only was lower in all three pairs (**13.171875–14.886719 MiB**) but approximately twice as slow. This supports the isolated construction mechanism, not a demonstrated complete-transfer or 896 MiB gate remedy.

The worker deliberately keeps `source` reachable throughout each full transfer (`benchmark/worker.mjs:28`, `:44`, `:56`), even after the mocked remote handle is disposed. It cannot isolate the real effect of releasing the remote graph in a different process. Receiver-only releases the source and explicitly collects before timing, while retaining all precomputed chunks for both implementations (`:30–32`, `:45–50`). It isolates decoding under those conditions, not a live transport with natural collection. The worker records checkpoint maxima and counts, not the sample-by-sample phase series (`:33–40`, `:55`); the isolated decoder has only start/end checkpoints. Process maximum RSS includes setup and assertions. These limits prevent attribution of the adverse full-transfer peaks to overlap, string backing, garbage collection, serializer temporaries, or allocator behavior.

## Bounded next decision

The missing evidence is **phase-aligned, process/cgroup attribution under the actual ownership model**, not another broad RSS sweep. A future explicitly scoped diagnostic would need fixed markers for measurement/serialization/read/disposal/decode/evidence-write boundaries, existing-budget memory-category observations and source identity, and full preservation of failures. It should distinguish Node heap/other memory, Chromium processes, and kernel cgroup anonymous/file/kernel memory without treating summed process RSS as cgroup usage. No forced GC, new wait, cadence increase, heap dump, extra serialization of results, retry, or gate relaxation should be inferred from this proposal. Exact instrumentation volume and overhead must be reviewed before any run.

The smallest unresolved decision is whether to authorize that bounded attribution experiment and identify the transfer/error-semantics baseline it may observe. No existing local correction warrants installation on current evidence. The separate observation-lifetime extension remains pending; this review neither adopts it nor permits a new pilot.
