# Prospective observation ownership amendment — proposal only

The approved criterion requires two distinct complete censuses: the first existing interval census wholly after final `browser.close()` settlement, and a later terminal census. The observed pilot has only the terminal census. The smallest feasible change is to allow bounded ownership of the existing sampler timer until the first scheduled post-close interval finishes. This changes the current **no-delay** instruction; it is not authorized by the previously approved cleanup criterion, not a reinterpretation of the stopped pilot, and not implemented in an active runner here.

## Concrete state machine

The proposal introduces no additional process, browser, worker or sampling call site. It owns a reference to the **existing** sampler timer; its phase, 100 ms cadence and fixed per-census read set are unchanged. Holding Node lifetime can cause an already scheduled census to execute that the old lifetime would not have reached; those real reads and records must be disclosed, not described as zero added observations. No immediate or replacement sample is introduced. A separate timer may check a bounded deadline, but must not sample. Any later implementation must preserve all retained raw samples, caps and original test assertions.

1. **WORKLOAD.** Existing measurements, 50 controls and interval telemetry proceed unchanged. Preserve the original source start and absolute internal deadline. No hold is acquired during measurement.
2. **CLOSING.** Immediately before the one final close call, acquire a reference to the existing interval timer. Keep the original absolute 90-second deadline active; do not clear it before close. Await the original close once, preserving its result/error. A close error, missing instrumentation, deadline expiration, or unexpected fallback permanently rejects cleanup acceptance; release acquired ownership and preserve failure evidence. No close retry is introduced. A deadline while normal final close is already pending marks failure and releases observation ownership; it must not issue a duplicate close or force browser termination to obtain a pass.
3. **WAIT_FIRST.** At successful close settlement, bind its exact `nextSampleIndex` and full clock stamp, requiring zero contexts. The effective cutoff is the **original absolute 90-second internal deadline**; no new grace period or numerical acceptance threshold is added. Ownership ends after the first scheduled attempt, regardless of its outcome. Never reset the internal deadline or timer phase. No immediate sample is taken.
4. **FIRST_ATTEMPT.** The next existing scheduled interval must have the bound index. Retain its entire process list and sequential read bounds through existing metadata paths. Every read must be wholly after settlement. The first attempt is decisive: clean, dirty, unreadable, malformed, cap-exhausted and write-failed outcomes all consume the ownership window. Release the sampler reference immediately after this attempt; never wait for a later cleaner census. Preserve any failure permanently. If no attempt completes before the effective cutoff, release ownership with cleanup `NOT_ESTABLISHED` and a failed internal budget gate. A callback arriving after cutoff cannot repair the failure. Check deadlines before and after the synchronous sweep so an overlong sweep cannot qualify.
5. **FINALIZING.** Perform the existing source artifact writes/readbacks and sidecar completion. These are real work, not synthetic liveness tasks. The sampler is again unreferenced; any scheduled intervals that occur naturally during these writes remain mandatory and must also be complete/clean. The original absolute internal deadline still applies. After caller finalization, remove that deadline's ability to keep Node alive (unref it rather than holding Node until 90 seconds); retain an exit-time clock check so delayed terminal work cannot evade the same cutoff. A pending ordinary operation that stalls is not granted more time. Original source outcome and any deadline/finalization failure must be separately preserved; a provisional measurement result never proves external cleanup.
6. **TERMINAL.** On natural process exit, take the existing single synchronous terminal census and close/write existing diagnostic evidence. It must be a later distinct sample with full nonoverlapping post-close bounds, exactly the original non-Z init and Node identities and no other process. Never relabel or duplicate the first interval or terminal sample. Check the absolute budget before and after terminal work; fail evidence completion if it expires. If final synchronous completion cannot persist its own late failure, a distinct nonzero exit and existing external time/telemetry checks must reject acceptance. The existing outer driver remains responsible for enforcement if the process or event loop stalls.
7. **EXTERNAL DECISION.** Unchanged independent validation requires normal browser child exit uniquely bound to logged PID/start ticks; no forced close/kill fallback; original source/container exit semantics; all first/later/terminal census rules; telemetry/sidecar/artifact I/O; final Docker state; exact zero-owned-resource cleanup; 896 MiB kernel observed peak; 128 tasks, 1 GiB hard limit, 2 CPUs, unchanged isolation/security/log caps; driver at most 90 seconds and outer deadline 120 seconds. None of these can be waived by the local observation promise resolving.

The ownership barrier resolves after the first **attempt**, not after success. Release must be in a `finally` path around the scheduled attempt, including an early sampler return caused by a prior failure or exhausted cap before its index increments; missing raw evidence then remains `NOT_ESTABLISHED`. A pending promise alone does not keep Node alive. Referencing the interval supplies that liveness, and the cutoff releases it. The absolute deadline continues through close, observation and evidence finalization; it is never rearmed for a fresh 90 seconds. At the original `startedAt` boundary, retain the existing wall-clock deadline and record a monotonic anchor; either clock reaching its original 90-second limit permanently expires the budget. The monotonic check prevents a backwards wall-clock adjustment from extending the new hold, while retaining the existing wall deadline avoids granting additional time after a forward adjustment. Neither anchor may be reset at close or finalization. The existing deadline-close behavior before normal finalization may remain, but any invocation is a failure for the successful-cleanup path. Once final close begins, deadline handling records failure instead of requesting another close. This handoff is an explicit prospective implementation requirement requiring independent tests before any runtime use.

JavaScript timers cannot preempt a blocked synchronous callback. The unchanged 100 ms cadence therefore does **not promise exit or a completed census within 100 ms**. A stalled timer can retain ownership until the unchanged absolute deadline; there is no separate observation grace budget. If the event loop runs late, entry/exit checks mark the attempt expired and release ownership at the first opportunity; outer enforcement and the unchanged driver gate remain. Even an on-time first census does not guarantee an on-time terminal census or a passing job. In the usual responsive case, ownership lasts only until the next cadence tick and its sweep, then releases immediately. The policy deliberately prefers failure over another interval, a new grace period, or a fabricated observation.

## Smallest unresolved decision

Approve or reject this exact **prospective bounded observation hold**: permit holding Node lifetime through its first existing 100 ms scheduled post-close interval, only until that first attempt or the original absolute internal 90-second deadline, whichever comes first, with first-attempt failures sticky and the separate terminal census still mandatory. The same amendment covers keeping the original deadline active through close/finalization instead of clearing it early. All other measurement and acceptance gates remain unchanged. This is a new behavioral permission because the existing instruction explicitly forbids delaying exit or adding grace to obtain a census. It does not renew or rescind the user's previous criterion approval, authorize another pilot, or solve the separate measured 896 MiB headroom failure.

If the no-delay prohibition must remain literal, retain the present `NOT_ESTABLISHED` outcome when natural lifetime supplies only the terminal census. Existing evidence does not support a guarantee of two distinct censuses under that prohibition. Counting terminal twice or replacing two censuses with one would change the evidence requirement and is not proposed.

## Offline evidence and limitations

`model.py` and `test_model.py` use only fabricated event timestamps, sample identities and outcomes. They make no real timer, browser, container, process-table, network or sampling calls. Their pure state transitions test the legacy missing-interval case; the prospective hold; exact first-index selection; dirty/unreadable first and later samples; identity/read-bound failures; terminal separation; sticky timeouts; close errors; unchanged memory and driver thresholds; and expiration during finalization. They do **not** demonstrate Node runtime integration, OS timing, memory reduction, independent process cleanup, or readiness for another pilot. The model simplifies full raw evidence validation; the existing reviewed cleanup validator remains the authority for actual sample schema/identity checks.
